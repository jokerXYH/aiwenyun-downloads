## Windows

- 免重启、不开 9222 调试端口。
- 只读扫描爱问云进程内存中的登录态（快速扫描约 0.3 秒）。
- 界面启用 Per-Monitor DPI 感知并按系统 DPI 缩放，150%/200% 缩放下字体
  不再被系统位图拉伸发虚；复选框改为自绘，避免原生 clam 主题的「X」记号。
- 8 线程 + 12 req/s 并发，33 个课堂实测约 3.8–4.0 秒（16 线程约 2.3 秒）。
- 单请求 6 秒硬超时 + 空连接回收 + 卡住看门狗，弱网不会无限卡住。
- 输出 `邀请码-时间.xlsx`（矩阵 + 明细）和 `…-诊断.json`。

## macOS

- 受 SIP / hardened runtime 限制，macOS 版需要关闭并重新打开爱问云，
  仅在本机 `127.0.0.1:9222` 开启调试端口，通过 CDP 读取登录态。
- 读取登录态后会自动恢复正常客户端窗口；导出期间客户端短暂重启属于正常现象。
- GUI 会弹窗确认重启；CLI 需要 `--allow-restart`。
- 未签名 / 未公证的包首次打开会被 Gatekeeper 拦截。macOS 15+ 已不支持
  右键 → 打开：先双击一次，然后到「系统设置 → 隐私与安全性 → 安全性」
  点「仍要打开」；或在终端执行：
  `xattr -dr com.apple.quarantine "/Applications/爱问云集成工具.app"`。
- 如果提示 `CERTIFICATE_VERIFY_FAILED ... unable to get local issuer certificate`，
  这是 macOS 打包版找不到 CA 根证书导致的。当前源码已改为优先使用
  `certifi`，重新构建即可。旧包可临时从终端启动：

  ```bash
  curl -L https://curl.se/ca/cacert.pem -o ~/Downloads/cacert.pem
  SSL_CERT_FILE=~/Downloads/cacert.pem \
    "/Applications/爱问云集成工具.app/Contents/MacOS/爱问云集成工具"
  ```
- 只在 macOS 12+ 上构建；未在真实 Mac 上人工测试，首次使用请保留日志。

## 稳定性设计（2.1.0）

- **快速扫描**：先扫主进程，通常 0.1–0.3 秒拿到 token；候选失效时自动完整重扫。
- **单请求看门狗**：邀请码请求 socket 超时 6 秒，另有线程看门狗强制断开，
  半死连接不会把工作线程挂住。
- **空闲连接回收**：连接空闲超过 5 秒直接换新，避免复用被服务端 / WAF
  悄悄关掉的连接——这是「爬到一半卡住」最常见的原因。
- **单课堂总截止**：每个课堂最多 22 秒、3 次尝试，到点记失败，绝不无限重试。
- **全局卡住看门狗**：整轮 28 秒没有任何课堂完成就收尾，进入第二阶段。
- **第二轮重试**：第一轮失败的课堂串行重试（预算 30 秒），网络抖动通常能补回来。
- **全局冷却**：超时 / 429 时所有线程一起停 0.7–1.3 秒，避免并发重试把链路打爆。
- **诊断文件**：每次导出在 Excel 旁边生成 `邀请码-…-诊断.json`，包含各阶段耗时、
  p50/p95、尝试次数和失败原因；别的机器卡住时把它发回来就能定位。

实测（33 个课堂，本机千兆网络）：

| 场景 | 结果 |
| --- | --- |
| 默认 8 线程 / 12 req/s | 33/33，约 3.8–4.0 秒 |
| 16 线程 / 30 req/s | 33/33，约 2.3–3.4 秒 |
| 24 线程 / 60 req/s | 33/33，约 2.2–2.4 秒 |
| 人为让 1 个请求卡死 9 秒 | 看门狗 6 秒收尾，第二轮补回，33/33 |
| 45% 请求随机失败 + token 过期 | 31/33，未卡死 |

手动压测（会请求真实接口）：

```bash
python tests/stress_live.py --rounds 2   # 服务器并发上限
python tests/simulate_stall.py           # 卡死/看门狗/第二轮
python tests/fault_injection.py          # 随机网络失败
```

## 板书导出（GUI）

程序顶部用「邀请码导出 / 板书导出」两个标签页把功能分开，互不挤压。
打开程序会先**只读检测本机已登录的爱问云客户端**：检测到就直接复用它的
登录态，全程不需要账号密码，也**不会把电脑客户端挤下线**。检测不到时才
显示账号密码登录（密码只在本进程内存中使用，不写日志、不落盘；同一账号
登录可能使电脑上的爱问云下线）。

板书列表按班级分组，点整行即可勾选：

1. 选时间段（默认最近 30 天；也支持全部 / 今天 / 最近 7 天 /
   最近一个季度 / 自定义起止日期），切换后会自动列出该时段的课堂清单；
2. 清单按**爱问云官方班级**分组：课堂会通过爱问云接口精确对应到班级，
   β1 / β2 / β3 / α1 等分组后缀会合并为同一个班（如 `2026027MA+31`，
   `作业班` 仍独立）；匹配不到班级的条目统一归入「杂项/未分类」，
   列表按时间倒序，最新的在最上面；
3. 每个班级行的「收起 / 展开」单元格可以折叠该班，右上角
   「折叠全部 / 展开全部」一次处理所有班级；点班级行其余位置仍是整组勾选；
4. 点「导出所选板书」——**只导出勾选项**，并先弹出**保存位置选择**；
   未勾选任何课时会被拦截，不会回退为全量导出；
5. 排序可选「按上课顺序」或「按板书类型」；PDF 按班级分文件夹保存，
   文件名与课堂名一致。

**进度与日志**：导出进度就在「板书导出」页内，位于时间/排序工具栏和班级
列表之间，包含总百分比、已完成节数、当前课堂页数（如「当前课堂 7 / 18 页」）、
已用时间和「取消」按钮；邀请码导出的进度则在邀请码页自己的面板里，不再挂
在另一个功能的运行日志下面。两个功能也各有独立的运行日志：邀请码日志在
邀请码页底部；板书日志在班级列表下方，默认收起，右侧显示未读条数，导出结束
或出错时会自动展开，也可以随时点「展开 / 收起」查看。

### 导出加速

板书页是很多张小 PNG，原来的串行实现把网络等待一层层串起来。现在做了：

- **班级并发 3 路 + 单课页面并发 4 路**：一节在等 `genBs` 时，其他课已经在
  下载；页数多的课也不会一页一页排队。可用
  `AIWENYUN_BOARD_CLASS_WORKERS`、`AIWENYUN_BOARD_PAGE_WORKERS`
  环境变量调小（服务端限速时）或调大（带宽充足时）。
- **HTTPS 长连接复用**：下载线程复用自己的 keep-alive 连接，避免每页重新
  TLS 握手；空闲过久自动换新，避免半死连接。
- **缩短 `genBs` 轮询**：从「0/15/20/30 秒」改为
  「0/2.5/4/6/8/10/12 秒」渐进轮询，服务端提前合成完就提前返回。
- **PDF 更省 CPU/内存**：每页下载后立即压缩成图像流，不再把整节课的 RGB
  原图同时留在内存；同名页复用同一个 PDF 图像对象；修掉了逐页全文件扫描
  定位 stream 的 O(n²) 写法；回读校验改为整文件比对 + 页数检查，不再逐页
  zlib 解压。
- **失败隔离**：一节课出错只记这一节失败，不再中断整批；429 会按
  `Retry-After` 退避重试一次；取消时页面下载和轮询会尽快停下。

本机实测（同一节 20 页板书，仅比较下载阶段，CDN 缓存已热）：

| 下载方式 | 耗时 |
| --- | --- |
| 每页新建 TLS 连接（旧实现） | 约 6.9 秒 |
| 单线程 + keep-alive | 约 1.1 秒 |
| 4 线程 + keep-alive（当前） | 约 0.46 秒 |

整节导出（含清单、合成等待和 PDF 写入）实测约 1.2 秒，输出 20 页、5.8 MB。
实际耗时会随课堂页数、网络和服务端合成状态变化，表中数字用于比较量级。

板书数据来自爱问云板书接口（`yxt/servlet/sign/getBsSign` → `upime/bs/genBs`
→ 服务端合成的逐页板书 PNG），全程只读。命令行用法见
`python banshu_export.py --help`。

## 安全

- token 只在本进程内存中使用，不写日志、不写 Excel/JSON。
- 错误信息中的 `access_token` 自动脱敏。
- 只允许 HTTPS 业务主机，使用系统证书校验，不跟随重定向。
- 不读取 cookie、localStorage、聊天记录或通讯录。
